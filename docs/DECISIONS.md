# Qiskit Resume — 결정 기록

## D-001 · 롤백 후 남은 무효 seq 처리 (2026-10-21)

**상황**
- 롤백은 "중단" 때문이 아니라 최신 chk가 **무효 판정**(파일 손상, revalidate 실패, workflow_id 불일치)일 때만 발생.
- `resolve`는 latest → latest-1 → … 순으로 내려가며 **처음 통과하는 seq**에서 재개. (6만 무효 → 5에서 재개)
- 6만 무효인 경우: 다음 commit이 6을 덮어쓰므로 대부분 자연 해소.
- 5·6 연속 무효 → 4에서 재개 → 새 5 저장 후 다시 kill → 디스크에 `새5 + 옛6` 공존 → 다음 재개 시 옛 실행의 6이 새 5 뒤에 섞일 수 있음. 실기(노이즈·shot·backend 변화)에서는 새 5 ≠ 옛 5 이므로 연결 자체가 성립 안 함.

**결정**
- 분기(parent_sequence / git식 브랜치)는 **불필요** — 채택 안 함.
- 재개 지점 k가 확정되면 **k보다 큰 seq 파일을 모두 치운다 (truncate)**.

**보관 방식 (결정)**
- 치운 파일은 삭제하지 않고 `steps/_invalid/`로 **이동 보관**.
- 동시에 `steps/_invalid/rollback_log.jsonl`에 한 줄씩 기록 — 나중에 "어디서 중단·무효였는지" 추적용.
  - 예: `{"at": "ISO-8601", "latest_before": 6, "resumed_from": 4, "moved": [5, 6], "reasons": {"6": "revalidate False", "5": "SchemaError: invalid JSON"}}`
- 파일명 충돌 시(같은 seq가 여러 번 무효) `seq_000006.<timestamp>.json` 식으로 구분.

**우선순위 (D-001)**
- 드문 엣지 케이스 방지 장치. B2(깨진 JSON 시 `SchemaError`로 크래시, 롤백 안 됨)보다 **낮음**.

## D-002 · 범용 재개 방식: Record & Replay (2026-10-21)

**목표 재확인**
- 특정 알고리즘(VQE 등)에 맞추는 것이 아니라, **양자 연산을 쓰는 모든 알고리즘**을 이 레이어 위에서 돌리면 중단 후 이어서 진행되게 하는 범용 보호장치.
- **1순위 사용처: IBM Quantum Open Plan 무료 할당량**(QPU 10분 / 28일 rolling window)을 여러 기간에 걸쳐 이어 쓰기.

**결정**
- 알고리즘별 키(iter/theta/…) 표준화 대신 **Primitive 호출(Estimator/Sampler) 단위 저널링**.
  - 1차 실행: 호출마다 입력 해시 + 결과 기록.
  - 재실행: 스크립트를 처음부터 돌리되, 기록된 호출은 실제 실행 없이 저장 결과 반환 → 끊긴 지점부터 실제 실행.
  - optimizer 상태·θ는 재생으로 자동 복원 (직렬화 불필요).
- commit 단위 = **Primitive 호출 1회** (고정). 저널 필드 = `index`, `input_hash`, `result`, `backend`, `job_id`, `usage`.
- 기록 오버헤드: IBM 실기 기준 무시 가능 → 수용. 로컬 시뮬은 테스트용이므로 성능 최적화(묶음 쓰기 등)는 후순위.

**파생 요구사항**
- `job_id`를 결과 대기 **전에** 기록 → 재시작 시 job 재연결 (이미 소비한 QPU 시간 재지불 방지).
- 호출별 QPU usage 기록 → 누적 사용량·rolling window 회복 시점 표시 (CLI status).
- 실행이 몇 주에 걸치므로 backend 캘리브레이션·Qiskit 버전 변화 기록 필요 (D3 on_backend_change와 연결).
- 결정론: 시작 시 random/numpy seed 자동 고정 및 저널에 저장. 입력 해시 불일치 시 이후 저널은 `_invalid/`로 이동 후 실제 실행 전환.
- 입력 해시: 회로 구조는 1회만 해시, 매 호출은 파라미터·관측량·shots·옵션만.
- Sampler: 기본 counts 저장, shot별 원본은 옵션.

**결정 (추가)**
- 호출 가로채기: **명시적 wrap** (사용자가 직접 감쌈 — 공개 API는 아래 D-003의 `resume.wrap`). monkey-patch 안 함 — README 원칙 유지.
  - 라이브러리 알고리즘(qiskit-algorithms VQE 등)은 생성자에 Estimator/Sampler를 인자로 받으므로 감싼 객체를 넘기면 커버됨.
- 결정론(seed 자동 고정·저장, 불일치 시 `_invalid/` 후 실제 실행 전환): **동의**.
- 저장 형식: JSON 파일 나열 대신 **자체 확장자** 사용 방향. 내부 컨테이너 형식은 논의 중 (D-004 예정).

- 일반 함수 결과 기록(구 `@resume.step`): **보조 기능으로 포함** — 공개 API는 `@resume.wrap` (D-003).
  - 표시한 일반 Python 함수의 **반환값**을 입력 해시 기준으로 기록 → 재생 시 즉시 반환 (예: 수십 분짜리 적분 계산).
  - 한계: 함수 도중 kill 시 재실행 / 부수효과(파일 쓰기·출력)는 재생 안 됨 / 반환값 직렬화 가능해야 함 / 입력 대비 결정론적이어야 함.
  - 범용 Python durable execution으로 범위 확장은 **하지 않음** — 본업은 양자 호출 보호.

**미정**
- 비-Primitive 경로(`backend.run`, `Statevector` 직접 계산) hook.

## D-003 · 공개 API 통일: `resume.wrap` 하나 (2026-10-21)

**결정**
- 보호 대상은 종류와 무관하게 **`resume.wrap` 하나**로 감싼다. 별도 `@step`, `wrap_primitive` 이름은 두지 않음.
  ```python
  estimator = resume.wrap(Estimator(backend))   # Primitive 객체 → 호출 기록 + job_id 재연결 + usage 추적
  sampler   = resume.wrap(Sampler(backend))

  @resume.wrap                                   # 일반 함수 → 반환값 기록 (보조 기능)
  def heavy_integrals(mol): ...
  ```
- 내부: 감싼 대상 종류(Primitive / callable)에 따라 동작 분기, **저널·입력 해시·재생 규칙은 단일**.

**이유**
- 사용자는 "보호할 것을 wrap으로 감싼다" 하나만 알면 됨.
- 반대로 전부 함수 데코레이터(@step)로 통일하면:
  1. 제출~결과 사이를 볼 수 없어 **IBM job_id 재연결 불가** (무료 할당량 절약 핵심 기능 상실).
  2. 라이브러리 알고리즘 내부 함수엔 데코레이터를 붙일 수 없음 — 객체 wrap은 인자로 넘겨 내부 호출까지 커버.

**영향**
- 기존 `wrap_primitive`, `touch`, `primitive_call_index` 기반 구현(l3/wrap)은 새 저널 구조로 교체 대상.

## D-004 · 저장 형식: SQLite 단일 파일 + 자체 확장자 (2026-10-22)

**결정**
- 실험 1개 = **SQLite DB 파일 1개**, 확장자는 **`.qresume`** (2026-10-22 확정 — 패키지명 qiskit-resume과 일치).
- 기존 `steps/seq_NNNNNN.json` 디렉터리 구조 대체.

**이유**
- 기록 중 kill·전원 차단에도 트랜잭션으로 파일이 깨지지 않음 → B2(깨진 JSON 크래시)·B3(fsync 없음) 대부분 해소.
- 단일 파일, Python 표준 내장(`sqlite3`), 수천 호출도 빠름.
- 프로세스가 죽으면 OS가 DB 락을 자동 해제 → B4(stale `.lock`) 해소.
- zip 컨테이너는 append 중 kill 시 전체 손상 위험 → 기각.

**영향**
- L0(fs)·L1(schema/checkpoint) 재작성. D-001의 `_invalid/` 격리는 DB 안 `invalid` 표시 + rollback 로그 테이블로 대응.
- 사람이 직접 못 읽음 → CLI(status / inspect / export-json) 필요.

## D-005 · 재생 매칭: 입력 해시 + transpile 캐시 (2026-10-22)

**결정**
- 재생 시 호출 매칭은 **입력 해시 우선**. 같은 해시가 여러 번 나오면 그 안에서 등장 순서로 구분.
- 해시 알고리즘: **SHA-256** (`hashlib`).
- 해시 입력: 회로 구조 + 파라미터 값(**유효숫자 12자리 반올림** — 머신 간 부동소수 끝자리 차이 흡수) + 관측량 + shots + 옵션.
- **변환기(pass manager)도 `resume.wrap`으로 감싼다** = 빌드 캐시.
  - 1차: 변환 전(원본) 회로 해시 → seed 자동 고정 후 transpile → `(원본해시, 장비이름) → 변환결과 X` 기록. **캐시 키에 장비 이름 포함** (D-007: X는 특정 장비 전용 회로).
  - 재생: 원본 해시 일치 시 변환기 실행 없이 기록된 X 반환 → 이후 Estimator 해시도 일치.
  - 감싸지 않은 경우: 변환 후 회로로 해시 + `seed_transpiler` 고정 권고 경고.

**이유**
- `seed_transpiler`를 고정해도 IBM 캘리브레이션(오류율)이 바뀌면 layout 선택이 달라져 변환 결과가 변할 수 있음 — 몇 주에 걸친 실행에서 재생 깨짐.
- 변환 후 회로만으로는 역변환 불가(게이트 분해·최적화·SWAP·재배치로 정보 소실) → X ≠ X' 일 때 "캘리브레이션 변화"인지 "사용자 회로 수정"인지 구별 불가. 원본 지문이 있어야 구별 가능.

**남은 연결 문제**
- 기록 이후 구간은 새 캘리브레이션/새 Qiskit으로 변환 → 앞뒤 기준 혼재. `on_backend_change` 정책에서 결정.

## D-006 · seed 관리와 재생 불일치 처리 (2026-10-22)

**seed — 3단계**
1. **자동 (사용자 할 일 없음)**: 실험 시작 시 seed 1개 생성·기록, 재실행 시 동일 seed 재사용.
   - Python 전역 `random`, numpy 전역 `np.random`
   - `qiskit_algorithms.utils.algorithm_globals.random_seed` (공개 설정값 — monkey-patch 아님)
2. **헬퍼 제공**
   - `resume.seed` : 기록되는 정수 seed. seed 인자를 받는 곳 어디든 사용 (`np.random.default_rng(resume.seed)`, `seed_transpiler=resume.seed`, `SPSA(seed=...)` 등).
   - `resume.rng()` : `np.random.default_rng(...)` 지름길. 호출 순서별 파생 seed(예: seed+1, seed+2…)로 매 호출 다른 스트림이되 재실행 시 동일.
3. **그 외** (seed 없는 `default_rng()`, 시간 기반 seed 등): 가로채지 않음 — 불일치 시 해시로 감지.

**가로채기(monkey-patch)로 RNG 씨앗 추출 — 기각**
- `rng.bit_generator.seed_seq.entropy`로 씨앗 값 자체는 존재하나, 생성 순간 기록·재실행 시 주입하려면 numpy 생성 함수를 가로채야 함.
- 사전 import된 함수·시간 기반 seed는 어차피 못 잡아 100% 불가 + 원칙 위반 + numpy 버전 의존 → 기각.

**재생 불일치 (입력 해시 다름) 기본 동작**
- 원인이 코드 수정·seed 변경이면 사용자 의도로 간주 → **경고 후 그 지점부터 실제 실행** (기본값).
- 경고 내용: 불일치 호출 번호, 달라진 부분(회로 / 파라미터 / 관측량 / shots — 부분별 해시 저장 필요), seed 없는 RNG 가능성 및 `resume.rng()` 권장 안내.
- 옵션 `on_divergence: stop` — 할당량 보호용, 불일치 시 실행 중단.

**보류**
- 스냅샷(사용자가 상태 변수를 직접 저장 → 재생 없이 해당 지점부터 시작) 옵션 기능 포함 여부. 기존 `commit/restore` 재활용 가능.

## D-007 · backend(장비) 변경 정책 (2026-10-22)

**배경**
- IBM 캘리브레이션(큐비트별 오류율 등)은 대략 하루 단위로 갱신되고 그 사이에도 계속 흔들림 → 특별 사건으로 취급할 이유 없음.
- 최적화형 알고리즘(VQE·QAOA)은 노이즈가 바뀌어도 대체로 재수렴. 단, 데이터를 **합산·평균**하는 실험은 조건이 섞이면 문제.
- 합산 실험의 정석: 장비 이름 고정 + 짧은 기간에 몰아서 실행 + **조건별 묶음 분석**.

**결정**
| 상황 | 동작 |
|---|---|
| 캘리브레이션 변화 | 무시 — **기록만** |
| 장비 변경 (1차 실행과 다른 장비) | **경고** + 기록 + 새 장비용으로 재변환 후 진행 |
| 옵션 `on_backend_change: stop` | 장비 변경 시 중단 (섞이면 안 되는 합산 실험용) |

- 호출마다 조건 기록: 장비 이름, 캘리브레이션 시각, 실행 시각, Qiskit/qiskit-ibm-runtime 버전.
- 변환 캐시(D-005) 키 = 원본 해시 + **장비 이름**. 장비 같으면 X 재사용, 바뀌면 재변환.
- (후속) CLI 묶음별 내보내기, 예: `export --group-by calibration|backend`.

## D-008 · IBM job 재연결 세부 동작 (2026-10-22)

재시작 시 기록된 `job_id`의 IBM 측 상태별 동작:

| job 상태 | 동작 |
|---|---|
| DONE | 결과만 받아 기록 (재제출 안 함) |
| RUNNING | 대기 후 결과 수신 |
| QUEUED | **대기** — 최대 대기 시간 설정 가능 (`job_wait_timeout_s`, 기본 무제한). 시간 초과 시 job은 **취소하지 않고** job_id 유지한 채 종료 → 다음 실행 때 다시 재연결 (줄 맨 뒤로 밀리지 않게) |
| CANCELLED | 재제출 |
| job 조회 불가 (기록 만료·계정 변경) | 재제출 |
| ERROR — 할당량 소진 | 재제출 안 함. 중단 + "할당량 회복 후 재실행" 안내 (회복 예상 시점 포함) |
| ERROR — 장비 오류·점검 | 재제출, **기본 최대 5회** (`job_max_retries`, 설정 가능) |
| ERROR — 회로 오류 (미지원 게이트 등) | 재제출 안 함. 중단 + 오류 보고 |

- 재제출·실패·대기 초과 등 모든 이벤트는 기록에 남김.

## D-009 · QPU 할당량 관리 (2026-10-22)

배경: IBM Open Plan = QPU 10분 / 28일 rolling window. 실행 중 소진 시 job 실패.

**결정**
- **(a) 추적 — 기본**: job마다 실제 QPU 사용 시간 기록 → 28일 rolling 누적 사용량, 다음 회복 시점 표시 (CLI status).
  - 한계: 이 도구를 거친 job만 집계. IBM 계정 실제 잔여량 직접 조회는 **하지 않음** (D-015).
- **(b) 예산 한도 — 기본 기능**: `qpu_budget_s` (예: 180). 한도 도달 시 다음 job 제출 없이 깔끔하게 중단 → 다음 실행 때 이어서 진행.
- **(c) 사전 추정 — 옵션**: 유사 이전 호출의 실제 사용량 평균 + 여유분으로 다음 job 비용 추정, 잔여 부족 시 제출 전 중단. 첫 호출(기록 없음)은 추정 불가.
- 할당량 소진으로 인한 job ERROR 처리는 D-008 참조.

## D-010 · 설정 출처: 코드 인자 단일화 (2026-10-22)

**배경**
- 여러 출처(설정 파일·환경변수·CLI) 계층은 사용자가 직접 실행하는 *도구*(git, pip, pytest…)의 방식.
- 이 프로젝트는 사용자 스크립트 안에서 호출되는 *라이브러리* → numpy·qiskit처럼 함수 인자로 충분.
- 기존 버그 B5: 디렉터리의 `resume_policy.yaml`이 코드 인자를 말없이 덮어씀.

**결정**
- 설정은 **코드 인자(`resume_run(...)`)만** 받음. 생략 시 기본값.
- 실험 파일(.qresume) 안의 설정은 **출처가 아니라 기록**: 매 실행 설정을 저장, 이전과 다르면 정보성 알림 ("설정 변경: qpu_budget_s 180 → 60") + 변경 이력 기록.
- **불변 설정**(seed, 실험 ID): 1차 실행 때 고정. 다른 값을 주면 오류 → "새 실험 파일로 시작" 안내.
- 실행용 CLI 옵션 없음. 사용자 스크립트의 명령줄 인자는 사용자가 argparse로 받아 코드 인자로 전달. 우리 CLI는 조회 전용(`status`, `export` 등).
- 결과: 우선순위 규칙 불필요, B5 구조적으로 해소. 기존 `resume_policy.yaml` 로드 로직 제거 대상.

## D-011 · 고전 계산 처리: 함수 wrap + 느린 함수 추천 + 스냅샷(v1 포함) (2026-10-22)

**고전 계산 자동 기록 — 기각**
- 많은 Python 함수가 반환값 외에 다른 객체 내부를 변경(부수효과). 예: PySCF `mf.kernel()`은 energy 반환 + `mf.mo_coeff` 저장.
- 반환값만 기록·재생하면 부수효과가 사라져 조용히 틀린 결과 → 어떤 함수가 안전한지는 작성자만 앎.
- 전체 함수 감시는 성능 저하 + 직렬화 불가 객체 다수.

**결정**
1. 고전 기록은 **사용자가 `@resume.wrap` 표시한 함수만** (D-003).
   - 부수효과 있는 코드는 "필요한 값(배열 등)을 반환하는 함수"로 묶어 감싸도록 안내.
2. **느린 함수 추천**: 1차 실행 후 재생 시 오래 걸릴 고전 함수 목록 출력 → 부수효과 없으면 wrap 권장. (기록이 아니라 알림만 — 안전)
3. **스냅샷 v1 포함** (사용자 결정).
   - 사용자가 상태(dict)를 직접 저장 → 재시작 시 해당 지점부터 시작, 이후 구간만 재생.
   - 스냅샷에 **저널 위치(호출 번호)** 함께 저장 → 스냅샷 이후 호출부터 저널과 해시 대조.
   - **RNG 상태 자동 포함**: 우리가 관리하는 seed 계열(전역 random·numpy, `resume.rng()` 스트림)의 현재 상태를 스냅샷에 자동 저장·복원 — 점프 후에도 랜덤 흐름 일치.
   - **저널 검증 안전장치**: 스냅샷 이후 첫 호출 해시가 저널과 다르면 → 스냅샷 상태 누락으로 판단 → 해당 스냅샷 무효 표시 + 경고. (Python은 되감을 수 없으므로) 다음 실행 시 이전 유효 스냅샷 또는 처음부터 재생.
   - 저널은 스냅샷과 무관하게 **항상 전부 보존** (스냅샷은 빨리 가기 위한 힌트일 뿐).
   - 스냅샷 빈도는 사용자가 결정. 여러 개 보관, 최신 유효본 사용.

## D-012 · 재생·스냅샷 검증 규칙 + 점검 도구(CLI 3종) + 실행 중 파일 복사 (2026-10-22)

**불일치 원인 구별 — 코드 지문**
- 실행마다 사용자 스크립트 파일 해시(코드 지문) 기록.
- 불일치 시:
  - 코드 지문 변경 → 의도적 수정 → **경고 후 진행** (D-006).
  - 코드 지문 동일 + 스냅샷에서 시작 → **스냅샷 상태 누락** → "스냅샷으로 이어가기 불가" 경고 + 스냅샷 무효 처리 + 실행 중단. 다음 실행은 이전 유효 스냅샷 또는 처음부터 재생.
  - 코드 지문 동일 + 처음부터 재생 → seed 없는 랜덤 등 → 경고 후 진행 (+ `resume.rng()` 안내).
- 스냅샷 검증은 스냅샷 이후 **이미 기록된 호출**과 대조하므로 IBM 전송 전에 일어남 → 할당량 손실 없음.
- 뒤에 검증할 기록 호출이 하나 이상 있는 스냅샷만 사용 (최신이 검증 불가면 이전 스냅샷 + 재생).
- `.qresume` 파일이 없으면 새 실험으로 시작 + "새 실험으로 시작합니다 (기존 기록 없음)" 안내.

**점검 도구 — 라이브러리 기능 (examples는 사용 흐름 시연)**
| 명령 | 대상 | 하는 일 | 비용 |
|---|---|---|---|
| `qresume status <file>` | 파일만 | 장비, 기록 호출 수, 스냅샷, QPU 사용량 표시 (코드 실행 안 함) | 0 |
| `qresume check <script> --file <file>` | 코드 + 파일 | 파일 무결성, 재생 해시 일치, 스냅샷 유효성, 코드 지문, 장비 동일 여부, 다음 실제 실행 시작 지점·예상 할당량 확인. 실제 실행 직전 정지 | 0 (재생만) |
| `qresume selftest <script> --backend local` | 코드 | 로컬 시뮬에서 끊김 없는 실행 vs 여러 지점 강제 중단·재개 결과 비교 → seed·스냅샷 누락을 IBM 사용 전에 검출 | 0 (로컬) |
- examples 흐름: selftest → IBM 실행 → (중단 시) check → 재실행.

**실행 중 파일 복사 후 check (사용 시나리오)**
- 사용자는 실행 도중 `.qresume`을 복사해 check로 확인 후 원 실행을 끊는 방식으로 사용할 것.
- ⚠ **실행 중 원시 파일 복사는 쓰기 도중 잘린(불완전/EOF 비정상) 사본이 될 가능성 높음**. SQLite WAL 모드면 본 파일만 복사 시 최근 기록(-wal)이 누락될 수도 있음.
- 대응:
  1. `qresume copy <src> <dst>` 제공 — SQLite 온라인 백업 API로 실행 중에도 **일관된 사본** 생성.
  2. `check`는 원본을 **읽기 전용**으로 직접 열 수 있게 (실행 중 쓰기와 동시 읽기 허용) → 복사 없이 점검 가능.
  3. 수동 복사본이 들어오면 `check`가 먼저 무결성 검사(`PRAGMA integrity_check`) → 실패 시 "쓰기 도중 복사된 파일 — `qresume copy` 사용" 안내. 기록 단위는 트랜잭션이므로 마지막 미완료 기록은 '없는 것'으로 취급.

## D-013 · 결과 저장 형식 (2026-10-22)

**결정**
1. **양자 호출 결과 = 우리 중립 형식** (Qiskit 공식 JSON·pickle 아님)
   - 기록 시 `PrimitiveResult` → 변환기 → 순수 데이터(배열 + 정보) / 재생 시 복원기 → 현재 Qiskit 버전 객체.
   - 저장 파일은 Qiskit 버전과 무관. Qiskit 변경 시 변환기·복원기만 수정. 대응 불가한 신버전이면 "Qiskit X 버전 이하 사용" 안내 가능.
   - Estimator: `evs`, `stds`, 메타데이터 / Sampler: 측정 비트 원본(packed bytes) + 비트 수·레지스터 이름·메타데이터 / 공통: **형식 버전 번호**, 기록 당시 Qiskit 버전.
   - 새 요소가 많이 생기면 우리 형식 버전을 올림 (옛 버전 읽기 유지).
   - 여러 Qiskit 버전으로 "기록 → 복원 → 동일" 자동 테스트.
2. **변환된 회로 = QPY** (Qiskit 공식, 구버전 파일 읽기 보장).
3. **사용자 값(함수 wrap 결과·스냅샷)**: 기본 타입 + numpy 배열. 그 외는 오류 + 변환 안내. `allow_pickle=True` 옵션(버전 경고). 저장 가능 여부는 기록 시점 즉시 검사(B7 재발 방지).
4. **바이너리 저장**: 숫자·배열은 텍스트(JSON)가 아니라 바이너리(float64 등) — 변환 비용 없음, 크기 축소, 정밀도 손실 없음.
5. **중복 제거(content-addressed)**: 회로·관측량 등은 해시를 키로 한 번만 저장, 호출 기록은 해시 참조 + θ + 결과만.
6. **Sampler 기본 = 원본(raw) 저장** (D-002의 "기본 counts" 변경). 이유: counts 복원 시 shot 순서가 달라져 재생 불일치 가능 / 무료 플랜 10분 한도로 총 shot 수 자체가 제한. 옵션 `sampler_storage="counts"`.
7. **압축은 내장하지 않음 — 별도 도구로 제공**
   - 실행 중 `.qresume`은 비압축 유지 → 실행 중 읽기(check)·도구 접근이 쉬움.
   - `qresume pack <file>` / `qresume unpack <file>` — 보관·수집·공유용 (zstd: Python 3.14+ 표준 `compression.zstd`, 그 이하 zlib).

**후속 아이디어 (기록만)**
- 실행 도중 의도적으로 파라미터를 바꿔 갈래를 만드는 사용 사례 → 특정 시점에서 실험을 복제해 다른 설정으로 이어가는 "fork" 기능 후보.

## D-014 · 의도적 갈래(force/fork), CLI 범위, 동시 실행 방지, 기록 정리 (2026-10-22)

**의도적 변경으로 이어가기 — 중요 사용 사례**
- 이미 쓴 QPU 시간(앞부분 기록)은 살리고 특정 지점부터 θ·optimizer·shots 등을 의도적으로 바꿔 이어가기 (국소 최저점 탈출, 다른 시도 비교 등).
- 불일치 알림 3단계:
  | 상황 | 알림 |
  |---|---|
  | 코드 수정(지문 변경) | ⚠ warning 후 진행 |
  | 코드 동일 + 스냅샷 이후 불일치 | ❌ error + "실수면 스냅샷 확인 / 의도면 `force=True`" 안내 |
  | `resume_run(..., force=True)` | 진행 + 이후 기존 기록은 삭제 없이 무효 보관(D-001) + "force로 갈라짐" 로그 |
- `qresume fork <src> --at-snapshot N --to <dst>`: 원본 파일을 건드리지 않고 새 파일로 갈래 생성 (= 복사 + force). 갈래 지점까지 원본 기록 재생(할당량 0), 이후 불일치는 예상된 것으로 처리. 중복 제거로 공통 부분 저장 부담 적음.

**CLI v1 (8종, 조회·관리용 — 실행 옵션 아님)**
`status` · `check` · `selftest` · `copy` · `export`(JSON/CSV, 조건별 묶음) · `pack`/`unpack` · `quota` · `fork`

**동시 실행 방지**
- 파일 이름은 사용자가 코드에서 직접 지정 (자동 고유 이름 없음 — 그래야 재실행 시 같은 파일을 찾아 이어감). 다른 실험은 다른 이름으로 동시 실행 가능.
- 막는 것: **같은 `.qresume`을 두 곳에서 동시에 실행(쓰기)** — 예: IBM 큐 대기로 멈춘 것처럼 보여 같은 스크립트를 다시 실행. 할당량 이중 소모·기록 꼬임 방지.
- 실행(쓰기)은 하나만, 두 번째 실행은 "이미 실행 중 (PC, 시작 시각, 상태)" 오류. 읽기(`status`/`check`/`copy`)는 동시 허용.
- 운영체제 파일 잠금 사용 → 프로세스 종료 시 자동 해제 (B4 해소).

**기록 정리 — 실행 중에는 아무것도 안 함 (2026-10-22 수정)**
- 원칙: **실행 중 속도 최우선** → 실행 중 자동 삭제·스냅샷 정리·압축 **일절 없음** (기록 추가만).
- 정리·압축은 실행이 끝난 뒤 **외부 도구로만**:
  - `qresume compact <file>`: 오래된 스냅샷 정리(기본 최신 5개 유지, 설정 가능), 무효 보관 기록 정리 옵션, DB 공간 회수(VACUUM). 옵션으로 검증된 스냅샷 이전 기록 삭제 — 그 이전부터의 재생 불가 경고.
  - `qresume pack` / `unpack`: 보관·공유용 압축 (내부적으로 compact 후 압축 가능).
- 정리 도구는 파일이 실행 중(쓰기 잠금 보유)이면 거부 → 실행 중 파일 손상 방지.

## D-015 · 제품화·의존성·IBM 실행 모드 확인 결과 (2026-10-22)

**제품화**
- 라이선스: **MIT**.
- PyPI 이름: **`qiskit-resume`** — 2026-10-22 기준 PyPI 미등록(사용 가능) 확인.
- IBM 계정 잔여 할당량 직접 조회: **하지 않음**. 우리 도구를 거친 사용량 기록(D-009 a)과 예산 한도(b)만 유지.

**IBM 실행 모드 확인 (공식 문서 기준)**
- Open Plan: **session 모드 사용 불가**, job 모드·batch 모드 사용 가능.
- primitive 생성 시 `mode=backend`(job) 또는 `mode=batch` / batch 컨텍스트 매니저 → `resume.wrap`은 두 경우 모두 지원 대상.
- batch 모드는 **제출 순서대로 실행 보장 안 됨** → 입력 해시 매칭(D-005)이 순서 기반보다 맞는 선택임을 재확인.
- batch 최대 TTL 도달 시 남은 대기 job 실패 → D-008의 ERROR 분류에 "TTL 만료 → 재제출" 추가.
- `RuntimeJobV2.status()` 값: `INITIALIZING`, `QUEUED`, `RUNNING`, `CANCELLED`, `DONE`, `ERROR` → `INITIALIZING`은 QUEUED와 동일 처리.
- `job.usage()`는 초 단위, 계산 완료 전엔 0 → 사용량은 job 완료 후 기록, 0이면 이후 재조회(status/quota 시 보충).
- 실패 원인 분류는 `job.error_message()` 사용. job 재연결은 `service.job(job_id)`.

**의존성 구성**
- Python ≥ 3.10 (압축: 3.14+ `compression.zstd`, 그 이하 zlib).
- 기본 설치 `qiskit-resume`: `qiskit>=1.0`, `numpy` (결과 변환·QPY·primitive wrap에 필요). 저장은 표준 `sqlite3`. **PyYAML 제거** (D-010으로 yaml 정책 파일 폐지).
- `[ibm]`: `qiskit-ibm-runtime` (job 재연결·usage 기록).
- `[examples]`: `qiskit-algorithms` (+ 화학 예제용 `pyscf` 선택).
- `[dev]`: `pytest`.

**보충: 실행 모드와 재제출 (2026-10-22)**
- IBM 실행 모드 3종: **job**(작업마다 개별 대기) / **batch**(독립 작업 묶음 제출, 순서 비보장, 장비 독점 없음) / **session**(장비 일정 시간 독점 예약, 반복형에 유리, Open Plan 불가). `resume.wrap`은 primitive의 `run()`을 감싸므로 **모드 무관하게 동작** — session도 유료 사용자용으로 지원 대상.
- 재시작 시 모드별: job — 특이점 없음 / batch — 해시 매칭, TTL 만료 job 재제출 / session — 프로세스 종료 후 session은 닫힘 → 사용자 코드가 새 session 생성, 닫힌 session의 미완료 job은 재제출.
- **재제출 원리**: 재생 중 해당 호출에 도달하면 사용자 코드가 같은 질문으로 `run()`을 다시 부름 → 기록된 job이 ERROR/CANCELLED면 그 호출을 평범하게 실제 실행(사용자의 현재 primitive 객체·모드로). 백그라운드 자동 제출 없음.
- 실행 중 장비 오류 재시도(최대 5회, D-008): wrap이 메모리에 든 질문으로 inner `run()` 재호출. 할당량 소진·회로 오류는 재시도 없이 중단.
- 질문(회로 QPY·θ·관측량·shots)은 이미 기록되므로, 향후 "실패 job만 기록으로 재실행" CLI 확장 가능 (v1 범위 아님).

## D-016 · 구현 중 확정된 세부 사항 (2026-10-22, P2~P10)

설계 결정을 구현하면서 생긴 구체화·수정 사항. 계약 정본은 `CONTRACTS.md`.

1. **회로 지문은 QPY가 아니라 구조 정규형** — QPY에는 실행마다 새로 생기는 Parameter UUID가 들어가 같은 회로도 지문이 달라짐. 명령 이름·큐비트·파라미터 이름·수치(12자리)·layout으로 정규형을 만듦. (변환 결과 *저장*은 그대로 QPY, 불러올 때 Parameter를 이름으로 사용자 것과 다시 연결.)
2. **12자리 정규화는 l0 codec 한 곳**(`canonical_floats`)에 두고 l1 hashing·l3 circuits가 공용 — 두 구현이 어긋날 위험 제거.
3. **코드 지문 = 스크립트 + 명령줄 인자** — 인자만 바꿔도 동작이 바뀌므로 '의도적 변경'으로 취급 (D-012 보완).
4. **스냅샷 검증 범위 = 스냅샷 이후 기록된 구간 전체** — 첫 호출만 맞고 몇 호출 뒤에 어긋나는 누락(예: 모멘텀)도 '스냅샷 누락'으로 잡음 (D-012 보완).
5. **느린 함수 추천은 프로파일링 대신 "호출 사이 고전 계산 시간" 측정** — 오버헤드 0. 종료 시 오래 걸린 구간의 위치(파일:줄)를 알려주고 함수로 묶어 wrap하도록 권장 (`slow_report_s`, D-011 구체화).
6. **selftest는 가짜 양자 결과** — 질문 지문으로 정해지는 결정적 값(올바른 shape). 시뮬레이터·QPU 불필요, 127큐빗 회로도 검사 가능 (D-012 구체화).
7. **check는 파일의 일관된 사본으로 동작** — 실행 중인 원본을 절대 건드리지 않음.
8. **실패·미제출 기록을 다시 실행할 때는 기존 기록을 무효 보관 후 새 기록** — 재시도 이력 보존 (D-001과 같은 원칙).
9. **`compact --before-snapshot`은 결과만 지우고 기록 행은 `compacted`로 남김** — 스냅샷 이후 재생 시 호출 순번 계산이 깨지지 않도록.
10. **예산 추정 = 같은 회로의 과거 QPU 사용 평균 × 1.2** — 남은 예산보다 크면 제출 전에 멈춤 (D-009 c).
11. **Qiskit 호환 범위 1.4 이상** — 1.4.6과 2.6.0에서 전체 테스트 통과 확인.

## D-017 · 저장 장소와 무관하게 같은 동작: 저널 모드 단일화 (2026-10-23)

**배경**
- Windows 실사용 중 W: 드라이브가 네트워크 공유(`\\10.35.23.2\smb`)여서 두 문제 발견:
  1. 읽기 전용 열기에 쓰던 `file:...?mode=ro` URI가 네트워크 경로를 거부 (`invalid uri authority`).
  2. SQLite WAL 모드는 공유 메모리가 필요해 네트워크 드라이브에서 안전하지 않음.
- 처음엔 네트워크 경로를 감지해 모드를 바꾸는 방식을 넣었으나, "어디든 상관없이 같은 동작"이 낫다고 결정.

**결정**
- 저널 모드를 **어디서나 rollback journal(DELETE) 하나**로 통일. 로컬 디스크·네트워크 공유·USB 구분·감지 없음.
- 읽기 전용 열기는 URI 대신 일반 경로 + `PRAGMA query_only`.

**대가와 근거**
- WAL보다 쓰기가 조금 느리지만, 이 라이브러리는 양자 호출 1회당 작은 트랜잭션 1개라 체감 차이 없음.
- 실행 중 `status`/`check`/`copy` 읽기도 그대로 가능: 쓰기 잠금은 수 ms, 읽기는 최대 30초 대기 (테스트로 확인).
- D-004·D-012의 WAL 관련 서술은 이 결정으로 대체.

**함께 고친 것**
- 시작이 느렸던 문제: 환경 정보 기록 때 qiskit_algorithms·scipy를 실제로 import하던 것을 패키지 메타데이터 읽기로 변경 (0.5초 미만). `algorithm_globals` seed 고정은 스크립트가 이미 import한 경우에만.

## D-018 · 표준 라이브러리 워크로드 대응 (2026-10-23)

**배경**: `examples/standard/`에 qiskit_algorithms의 VQE(SPSA)·QAOA·VQD를 수정 없이 올려 돌려보며 실제 문제 3개와 정규형 문제 1개 발견.

**결정**
1. **스레드 안전** — qiskit_algorithms는 primitive를 worker 스레드에서 호출. SQLite 연결을 `check_same_thread=False`로 열고, 모든 판정·기록을 `ExperimentDB.lock`(RLock)으로 직렬화.
2. **isinstance 호환** — 감싼 primitive를 `BaseEstimatorV2`/`BaseSamplerV2`의 실제 하위 클래스(`WrappedEstimator`/`WrappedSampler`)로. 라이브러리 타입 검사를 그대로 통과.
3. **매개변수 식의 정규형** — `1*γ[0]`과 `γ[0]`처럼 같은 식이 QPY 왕복·재바인딩 후 다르게 출력됨. 문자열 대신 **매개변수 이름 + 이름에서 정한 두 시험점에서의 값(12자리)**으로 식을 식별. 이 때문에 QAOA 재개 후 마지막 호출이 '다른 질문'으로 판정되던 문제 해결.
4. **QAOA 예제는 transpile을 감싸서 사용** — 분해하지 않은 PauliEvolutionGate는 시뮬레이터가 2^n×2^n 행렬을 만들어 메모리 초과. 하드웨어와 같이 기본 게이트로 분해(캐시됨).

**영향**: 3번으로 기호 매개변수가 있는 회로의 질문 해시가 바뀜 — 0.2.0.dev0 이전에 만든 `.qresume`과는 해당 호출이 맞지 않을 수 있음(개발판이라 허용).

## D-019 · 예제 = 순수 Qiskit, 보호·강제중단은 실행기가 담당 (2026-10-23)

- `examples/standard/*.py`는 qiskit-resume를 전혀 import하지 않는 **순수 Qiskit 코드**. 단독 실행 가능.
- 실행기 `examples/crash_and_resume.py`가 예제를 불러와 primitive를 `resume.wrap`으로 감싸고, 1차 실행을 **강제 종료**(OS kill)한 뒤 같은 명령을 다시 실행. `--compare`면 중단 없는 실행과 결과 일치 확인.
- 예제가 제공할 것: `SEED`, `build_primitives(seed)`, `main(**primitives, **params)` — 몽키패치 없이 primitive를 주입하는 일반적인 의존성 주입 방식 (D-003 유지).
- 콘솔 로그: `resume_run(..., log_calls=True)` 추가 — 호출마다 `call #N kind: execute|replay` 한 줄, 재생→실행 전환 시점 표시.

## D-020 · AI가 그대로 적용할 수 있는 API: 장비·변환·난수 실수를 코드로 막기 (2026-10-25)

**배경**: 기존 스크립트에 적용할 때 사람·AI가 놓치기 쉬운 점이 넷 — (1) pass manager를 `backend=`와 함께 감싸고 `seed_transpiler`를 고정, (2) 시드 없는 난수 교체, (3) 재실행 때 장비 고정, (4) 적용 후 selftest 확인. 문서 경고보다 **틀릴 여지를 코드에서 없애는** 쪽을 택함.

**결정**
1. `resume.pass_manager(backend, **preset_args)` — `generate_preset_pass_manager` 자리에 그대로 대체. 장비 연결·고정 `seed_transpiler`(`seed_for("transpile")`)·기록을 한 번에. 처음 쓸 때 생성하므로 `resume_run` 밖에서 만들어도 됨.
2. `resume.backend(service=None, name=None)` — 첫 실행에 장비(지정 또는 가장 한가한 것)를 고르고 실험 파일에 기록, 재실행은 기록된 장비. 다른 `name`을 주면 의도적 변경으로 보고 `on_backend_change` 규칙 적용.
3. 난수: **numpy를 몰래 바꾸지 않음**(D-003 유지). 대신 `resume.rng(name=None, *, seed=None)`과 `resume.seed_for(name)` 제공.
   - 이름 있는 스트림은 호출 순서와 무관 → 난수가 여러 개 필요한 코드에서 순서를 바꿔도 안전.
   - 이름 없는 `rng()`는 기존처럼 호출 순서 기반(호환).
   - 시드 없는 numpy 호출은 사용자가(또는 AI가) `resume.rng("용도")`로 교체 — 가이드 규칙으로 명시.
4. 놓친 경우는 `qresume selftest`가 QPU 전에 잡고, 기록과 달라진 **호출의 소스 위치**(`made at file.py:줄`)까지 알려 줌.
5. `@resume.wrap` 함수의 반환값·인자로 `SparsePauliOp`·`QuantumCircuit` 지원 — 느린 고전 계산(예: 분자 해밀토니안 생성)이 보통 이 타입을 돌려주기 때문.
6. 이름 있는 `resume.rng("x")`는 이름당 하나의 Generator 객체(반복문 안에서 호출해도 같은 값 반복 없음). AI 적용 시험에서 발견한 함정을 코드로 막음.
7. 적용 가이드를 세 곳에: README "Add it to your script"(전/후 코드 + 규칙), 저장소 루트 `llms.txt`(AI 도구용), 패키지 docstring(`help(qiskit_resume)`).

**검토한 대안**: `resume_run` 동안 `np.random.default_rng(None)`을 자동 고정 — 코드 수정이 필요 없지만 숨은 동작이고 D-003과 충돌해 기각.

**검증**: 독립 에이전트 2회가 `llms.txt`만 보고 순수 Qiskit 스크립트 6개(VQE, QAOA, 스윕, VQD+SPSA, 느린 고전 단계, IBM)를 변환 — 로컬 5개 모두 selftest 첫 시도 통과, 두 번째 실행 0회 실행. 발견된 가이드 공백(반복문 속 rng, least_busy 필터, 느린 함수, with 블록 범위 등)은 코드·가이드에 반영.
